# Gothic 3 VR 0.22.6 — retain current pose when acquiring2H support

The live report describes an approximately45-degree rightward snap when grabbing a2H weapon with the left hand after rigid palm attachments were introduced. The prior support acquisition computed a new rotation from the weapon shaft to the raw controller-centre line. Calibration offsets and rigid visual palm alignment make those axes differ; the code therefore moved the entire locked hand/weapon assembly abruptly. Existing palm-contact tests verified the binding after acquisition but did not compare the before/after weapon pose.

Support now captures the current rendered primary grip/mesh directly. It no longer aligns the shaft to the raw hand-centre line on acquisition. The subsequent coordinated solver transports this captured frame as both hands move and retains the existing averaged wrist twist, locked support point, and primary item-to-hand transform. The same captured orientation is mapped from world space into raw tracking space for combat, so camera/player motion cannot become a physical swing. Both render and tracking captures are reset if either fails.

For heavy swords/axes the existing unsupported weight pose is applied before support detection/capture. This is the pose already shown to the player; grabbing support must not discard its current weight lag. Weight is applied once per pose rather than twice. The weighting curve, one-hand penalty and skill/stamina/damage rules are unchanged. Staff support uses the same acquisition helper while retaining its existing separate mesh/palm profile. Bow/crossbow handling and1H/dual-wield locked attachments are unchanged.

71/71 tests pass. The expanded rigid-attachment regression checks swords/axes, both grip directions, an oblique45-degree raw hand line, nonzero hand/profile calibration and current unsupported weight. The very first supported pose reproduces the previous mesh; then both palm bindings and rendered/tracking orientations remain coherent through large rotations and native world movement between duplicate XR timestamps. Relative contacts are measured in local coordinates to avoid cancellation from40,000cm absolute world positions; tolerances were not widened. Existing coordinated-grip twist/pole/stereo/recovery tests pass.

The launcher and resolution patch are unchanged binaries retained from0.22.5 (launcher originally validated in0.22.4 with15 pages). Existing user INI and calibrations are preserved. Native modules/assets are unchanged. The package includes source, built binaries and verification evidence. Live sword/axe support acquisition and movement still need the user's headset confirmation; the game is not launched unattended. Logs include vr_two_hand_acquire with current_rendered_pose=1, weight_retained and axis_realign=0.
