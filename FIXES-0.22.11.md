# Gothic3VR0.22.11 — Flame Sword ghost layer and menu staff

The accepted0.22.10 hand/palm/2H implementation is byte-identical. This release addresses two separate visual problems with the existing game effects and menus. No controller settings, hand offsets, damage, stamina, skill progression, locomotion or ranged mechanics change.

Flame Sword: the native eff_magic_weapons_flamesword_01 sequence spawns six TargetEntity-linked children. Local template inspection shows VFX_Magic_Weapons_FlameSword_01 is an independent/world-space fire emitter(max900 particles,900/s,.2-.35s lifetime), while03 is a relative/blade-space fire emitter(max60,30/s) using the exact same fire texture.04 is a second world-space tail(max100,400/s,.4-.8s);02 is local glow(max10,5/s). A controller-tracked blade can move faster and independently of the native animated emitter history, exposing the delayed world-space copy. See weapon-effects-evidence-0.22.11.json for the read-only asset inspection and hashes. No native assets are included in the package or modified on disk.

The plugin now bypasses native eCParticle_PS::OnProcess and OnRenderAlpha only for the exact01/04 world-space, non-instanced layers whose live parent chain reaches a currently held player1H Flame Sword or Magic Flame Sword. The relative03 flame and02 glow remain native and follow the blade. NPC weapons, environmental fire, unrelated spell effects, dropped swords and third-person/native rendering use their original callbacks. There is no extra fire system, new emitter spawn, entity deletion, shared particle-array edit or persistent entity pointer. Both optional hooks require the already verified Engine hash, exact named export RVAs and complete relocation-free prologues; partial installation or an ownership fault forwards all native effects. World teardown blocks owner queries. The hooks use the original thiscall ABI; the alpha callback retains its signed short pass argument. Performance improvement is not measured yet; expensive world-tail simulation and draw calls are skipped when the owner/VR gates match.

Menu staff: BeginTrackedArms intentionally skips native menus, so the game previously left its default upright staff in view. In tracked first-person VR, a menu or radial now collects the player's currently held Staff/Halberd tree, hides it for both world-eye renders, then restores each original render flag in parent-before-child order. This includes separate magic-offhand staffs. Collection is bounded and precedes all writes; incomplete capture preserves the native tree. The scope does not change equipment, item transforms, alpha, staff grip settings, arm IK, spells or NPCs. Third-person dialogue/activities keep their native equipment. All pointers are frame-local. Existing gameplay support and menu pointer behavior stay unchanged.

A separate real-binary test confirms the two hook entry prologues, the opaque particle render no-op and Game::Execute TargetEntity/TargetBone branch to CreateChildEntityFromTemplate.
