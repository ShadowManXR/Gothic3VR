# Gothic 3 VR 0.18.1 — world teardown lifecycle

The user reported an access violation on closing Gothic 3 after testing 0.18.0. The native report, raw stack and loaded-module map were preserved locally. EIP 02A9A420 maps to Engine.dll RVA FA420, ComputeSHOcclusion +150; the failing instruction dereferences EDX=20AA0C02. The native symbolic callstack is empty. The diagnostic log records repeated physical-bow access violations from 92.845 seconds, before engine shutdown at 97.610 seconds. These establish an unsafe VR ownership/lifecycle path; they do not prove that it alone caused the native ambient-occlusion failure.

VR bindings now restore before native session Stop clears the player references. An inline Stop hook verifies the full Game.dll hash, export RVA1741C0 and all nine prologue bytes with the relocated absolute IAT operand. Reentrant mod updates are blocked during native teardown. The native Stop callback still executes and its exceptions remain native. After Stop, old ammunition ownership is forgotten without touching entity/inventory pointers; a later loaded game can resume VR normally.

The EXE OnDestroyWorkspace override (SDK slot166, verified RVA4160) now restores world bindings and disconnects stereo before native workspace/world resources are released. Existing OnDestroyEngine cleanup remains as a later fallback. Both shutdown flags permanently block mod entity updates during exit. Native slot166 calls Game::OnDestroyWorkspace and workspace RemoveAll; no native resource/ambient-occlusion function is patched or suppressed.

Physical-bow updates with no current player/game abandon ownership directly. The optional crossbow-retention branch evaluates native entity arguments only when retention is actually allowed. A guarded physical-bow failure also forgets retained pointers immediately instead of repeatedly revisiting the failed ownership. Normal in-game draw, charge, damage, skills and ammunition semantics remain; BowCharge.h, PhysicalBow.h and CrossbowHandling.h are unchanged from the accepted 0.17.1 version.

Inspection also found that unrelated NPC physics callbacks reset the single VR GroundMotor every frame. Reset now applies only to its owning movement object. A regression with thirty interleaved NPC callbacks verifies the player's starting response reaches its intended speed. Direct movement mechanics and user response settings otherwise remain as in 0.18.0.

61/61 tests pass, including nested teardown/reentrant entity gates, new-world resume, SDK slots165/166, actual relocated EXE workspace target, actual Game Stop prologue/player-clearing instructions, a hundred x86 void-thiscall Stop trampoline calls through a copied absolute IAT operand, and actor-isolated locomotion. Existing ranged, melee, magic, room-scale, UI and GPU tests pass. Launcher code/binary are unchanged; the 0.18.0 13-page layout check remains applicable. Installer skips overwriting an identical launcher, allowing a plugin-only update while settings remain open. User INI is preserved exactly and replaced binaries are backed up.

Next probe: load the save, equip/use a ranged weapon, return to the menu and load again, then exit normally. Verify reload/draw/aim are retained and no error appears on exit. Logs should include vr_world_stop_begin/complete and stereo_workspace_shutdown_begin before stereo_engine_shutdown_begin, without repeated physical-bow faults. The reported native crash is not considered confirmed resolved until a live exit test succeeds. Game is not launched unattended.
