# Gothic 3 VR 0.22.7 — nocked and launched ammunition visibility

The report affects both held arrows/bolts and projectiles in flight. The recent live log contains 28 successful native Shoot calls with one projectile callback and one ammunition decrement per shot. Its render-binding entries contain animated bows/crossbows but no arrow/bolt bindings. NativeTrackedBow previously required an animation factory for every item; static ammo was skipped. The hero-palette fallback moved ammo but did not request visibility, depended on the hero actually rendering, and could compete with the weapon renderer's pose/restoration.

Nocked ammo now has a separate static or animated binding in NativeTrackedBow. Before each eye's frustum traversal it applies the accepted string/bolt geometry, enables visibility and sets opacity. The binding must match the current player, equipped ranged weapon, exact right-hand inventory entity and arrow/bolt type, with a non-flying projectile property set. The hero-palette attachment pass yields all ranged weapons and ammo to this single owner. Hero palette cache hits/culling cannot prevent the held static projectile from being positioned.

EnableRendering recursively changes native children. A bounded per-eye visual scope collects the entire item tree before mutation and restores parent then children, recovering each original visibility flag and opacity exactly. Ammo scopes unwind before weapon scopes, preserving nested attachments. Local transforms and animated palettes are also restored. Failed ownership or save/equipment replacement discards borrowed snapshots instead of touching the new entity. No projectile pointer is retained after launch or shutdown.

At the verified, owned native projectile Shoot callback, the newly spawned arrow/bolt is explicitly enabled and made opaque once before native flight starts. This hardens the launched path against invisible initial state; the old log did not record launched alpha/visibility, so headset confirmation remains necessary. Native impacts, effects, special ammo and decay still own its lifetime. NPC projectiles and already-flying entities are excluded. New log entry vr_ranged_projectile_visible records its original visibility/alpha; vr_bow_render_binding now reports animated=0 for static ammo.

Bow charge, draw timing/progression, arrow velocity/damage, crossbow reload profile/timers and ammo consumption are unchanged. Source comparisons prove the original NativeBow shooting, inventory, reload, update and ballistics logic is retained except for the added visibility step. The accepted current-pose 2H acquisition fix, grip locking, native movement, controls, Sneak restriction, camera and launcher settings remain.

72/72 tests pass. New regression coverage reproduces recursive native visibility, both eyes, combat hiding, repeated arrow/bolt slot replacements, launched/held separation, native flight/decay and NPC gates, bounded collection, and SEH render cleanup. Existing native binary/ABI, bow progression, crossbow reload, grip and GPU stereo tests pass. The unchanged launcher/patch binaries and prior fifteen-page launcher validation are retained with provenance. The installer preserves the latest user INI and backs up binaries. No unattended game test was launched.

Headset probe: fire at least 10 arrows and 10 bolts in combat; watch the loaded ammo before/after taking damage and the projectiles in flight. Also test equip/holster, quick-slot switching and a save reload. The visual result is pending user confirmation.
