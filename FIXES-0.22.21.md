# 0.22.21 — empty finish searches, ranged ownership, native profiling

With no eligible finishing target, a negative search result is reused for up to80ms. No native entity pointer is retained. Positive focus and the actual right-trigger/right-grip execution chord continue full-rate searches. Player/weapon/session changes, tracking invalidation and world stop reset the gate. The idle hint can appear up to80ms later for a newly eligible target; pressing the chord forces immediate validation. Target rules, animation, skills and damage are unchanged.

VR draw cancellation no longer re-equips borrowed ammo with EquipStackToSlot during native menu/equipment/recovery transitions. It drops the VR borrow without calling native inventory methods. The native game owns holstering/slot cleanup, and the next valid Nock reacquires the current ammo stack. Fire resolves the current right-hand slot and stack before touching a previously borrowed arrow/bolt. This also removes the old keep-crossbow predicate that evaluated a stale ammo argument before ownership was established. Native Shoot still consumes exactly one real item and retains existing skill/reload/charge behavior. The observed access violation was recovered during a ranged-to-menu transition; exact root cause could not be proven from the old log. These changes remove the unsafe inventory restoration/dereference paths, but need a live regression test.

Recovered ranged exceptions now retain operation, instruction address, module/RVA and accessed address, rather than only the exception code. Existing bounded retry and fresh-trigger behavior are preserved. The existing VR ranged recovery handler gains diagnostics.

Native gCSession::Process timing uses a hash-verified, symbol/virtual-target-verified wrapper and chains to the current native target. Unrecognized profiles skip this profiler and leave gameplay unchanged. Its collector is independent of the application OnProcess callback, as session/focus work can execute outside that callback. Controller-focus timings include their VR camera scope and overlap session processing. These phases still do not cover the entire engine loop.

The old native_update_inclusive label is corrected to application_process_callback. This is a naming/scope correction; its tiny0.22.20 readings never established full engine simulation cost. Reports now state this limitation explicitly. Native-phase reports give means per call, distinct from VR means per update.

CPU stages exceeding20ms emit a bounded spike record with stage, XR frame serial, thread and QPC clock. Per-stage rate limiting is250ms; nested stages overlap, and the records are not an exhaustive hitch histogram. No additional GPU waits, readbacks, visual-quality reduction or cross-frame image queue is introduced. The native-render266ms spike is under investigation, not claimed fixed.

Analyze-Performance.ps1 retains the frame/bridge report; Analyze-UpdatePerformance.ps1 reports controller/combat costs with corrected scope notes; Analyze-NativePerformance.ps1 reports native session/focus and individual slow stages. A comparable gameplay run is needed to establish real gains and identify the remaining native-render hitch.

Validation:91/91 tests pass, including negative-search cadence, immediate positive focus/chord, ammo replacement before entity access, independent native-phase collection and the SDK's Release Process dispatch thunk. The analyzer passed weighted per-call means, separated contexts, zero calls, spike ordering and truncated-tail fixtures. Compiled-plugin FMOD compatibility passed. Gameplay and the native session hook still need live validation; no FPS gain or fix for the native-render spike is claimed.
