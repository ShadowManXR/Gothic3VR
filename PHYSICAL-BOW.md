## Native mesh and string

The installed animation archive includes each bow's `*_Cock.xmot` and `*_Relax.xmot`. The native Cock motion rotates four limb/tip bones and deforms the skinned string. The Army Composite model's Bone01 joint is (-0.118, 0, -25.287), at the lower handle endpoint rather than the actual grip centre, its rest string centre is approximately (-27.041, 0, -12.180), and its full native string travel is 45.187 game units. Model origin and the arrow support are not the lower holding point. Rigid handle triangle intersections at string height identify the handle cross-section. The shaft rest is on its rear left edge (model negative Y), with 0.6 game units of radius clearance. The grip retains the original lower Bone01 position. Tip/string triangles are excluded through Bone01 skin weights. Malformed indices or a missing cross-section refuse the model.

BowModel reads the equipped model and Cock motion through the SDK virtual filesystem. It validates chunk bounds, parent hierarchy, mesh/skin weights and rotation keys; supports multiple materials and the native static mesh track naming inconsistencies. The four string-centre vertices identify the nock point with their actual skin weights, including small secondary influences. Native animation time is solved from the physical backward draw distance and clamped to the model's maximum travel. Every bow render receives an evaluated skinning palette; shared actor transforms and animation playback are never mutated. Before frustum selection for each eye, the equipped bow and any animated held arrow borrow their tracked world transform through SetToWorldMatrix. This updates spatial dependencies and avoids visibility being tested at the native carry pose. Local transforms, palette and frame cache are restored after each stereo eye and in the render finally block. Left-hand tracking alone keeps the bow and sight available; right-hand tracking loss cancels draw without hiding the bow. No stale left-hand pose is held. NPC bows remain on their native path.

The arrow tail is placed at the evaluated string centre using its own local bounding box. Its shaft points from that nock past the left-side handle rest, including native string travel. The same evaluated shaft direction and nock origin drive the visible arrow, stereo crosshair, native focus and projectile. Drawing power uses longitudinal travel along the filtered bow aim, so the small shaft angle does not charge from lateral motion. Existing native ammunition reacquisition prepares the next arrow after release without creating ammunition. The crosshair indicates initial launch direction, rather than gravity-compensated landing position.

## Native shot pipeline

Game.dll, Script.dll and Script_Game.dll hashes gate the integration. The verified native Shoot callback (Script_Game RVA 0x86450, stdcall, ret 16) spawns and owns the hero's projectile, adds bow/arrow damage, consumes one arrow and returns remaining ammo to slot 14. The named PSProjectile::Shoot import at RVA 0xE4834 is intercepted only during that synchronous hero release on the application thread. The arrow tail is anchored at the launch nock point, its local +Z follows the evaluated shaft direction derived from filtered left aim, target lock is cleared and native Physics flight/collision/gravity/damage remain active. Each bow release initializes DamageHitMultiplier to the native `0.2 + 0.8 * charge` and velocity to `200 * that multiplier`, independent of old held-arrow values. Readiness and physical draw both limit charge; there is no square-root velocity curve or second multiplication. There is no attack click, direct HP subtraction or ammunition creation. Missing/duplicate launches disable physical bow input and are logged.

HoldStackRightHand's return value is false even after a successful link in the installed native Game implementation (RVA B84AD); actual right-slot contents therefore verify nocking. Menus, radial, loss of focus/tracking, recovery, weapon changes, camera reset and settings changes cancel the draw. A temporarily held ammo stack is restored only if it is still the same stack; a new selected weapon is not overwritten. Crossbows remain a separate future integration.
