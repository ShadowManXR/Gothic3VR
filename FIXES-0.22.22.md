# 0.22.22 — isolate native first-eye hitches

This is a diagnostic release. Live0.22.21 logs put several gameplay hitches inside original first-eye rendering (106–228ms); these timings do not identify a native root cause. Native session Process and controller focus were small in that run. The first arrow took about57ms in the ranged update without a recovered fault. No FPS improvement or hitch fix is claimed for0.22.22.

Five original Engine phases are timed inclusively: frustum Update, ExtractFromFrustum, ExtractFromFrustumOC, Execute, and RenderSystemAdmin::Render. Installation requires the exact accepted Engine.dll SHA256, matching export RVA, and a full verified position-independent instruction prefix. Each wrapper calls its original exactly once. An unavailable entry is skipped; the startup mask reports which profilers installed. Timings apply only to the original VR eye render on the application thread. The phases can nest and must not be added together. The native render list, culling, both-eye frusta and scene states are unchanged. FlushThreadQueues is deliberately not hooked because its entry would require instruction relocation.

The four existing D3D9 draw wrappers also measure the CPU wall time of their original draw API calls during each eye. Fixed storage and clocks are used; the hooks add no GPU queries, waits, state changes, log writes or resource allocation. Nesting contributes once to elapsed draw time. Draw calls remain unchanged and execute once. Eye samples report total CPU time, draw-API CPU time, the remainder, longest original draw call and four call counts. The remainder includes both scene preparation and OTHER driver/API work (states, resource/shader setup); it is not pure engine CPU time. CPU draw time is not GPU duration. Existing sparse, nonblocking GPU timestamps remain separate.

Normal eye records are sampled every2seconds per eye. Hitches of20ms or more are sampled with a250ms per-eye limit. This is not an exhaustive histogram or a frame-weighted average. G3VR_DRAW_PROFILE=0 disables per-draw clocks for overhead comparison in a new process. Native phase collection remains enabled. Profiling clock/callback overhead is included in outer scopes and must be considered when comparing runs.

Native phase and spike lines produced during an eye are buffered in16 fixed4096-byte slots and written only after the CPU interval and GPU end timestamp close. Overflow drops telemetry and emits a count; it never stalls rendering to wait for queue space. Cancellation clears the active draw scope and drains pending lines outside that scope. This avoids synchronous file flushes inside the original eye interval; logging still takes time elsewhere on the application thread.

Ranged timings now separate the original native Shoot script (inclusive), VR projectile preparation and original native projectile Shoot. Existing ammo ownership, progression, charge, speed and reload behavior are retained. A new first-shot session is needed to locate the cold-shot cost.

Analyze-NativePerformance.ps1 reports native phases, CPU spikes with eye/frame IDs, the largest eye draw spikes and recent ordinary samples. It keeps contexts separate, handles missing older phase names and ignores an incomplete final line. Interpretation limits are included in its JSON output.

Validation:93/93 tests pass (26.71seconds), including real Engine export/RVA/prefix validation and clock/nested-call/cancellation tests. The actual D3D9 UI test confirms that all four timed original draw methods still paint the same desktop pixels, preserve UI counts and cancel cleanly, with native state/hook restoration. The bounded profiler queue passes overflow and failed-drain checks. The synthetic100000-call timing loop took6.911ms including clocks; this is not a measurement of game overhead. Analyzer fixtures pass separate contexts, weighted native means, spike ordering, ordinary eye samples, dropped lines and a truncated tail. Compiled-plugin FMOD compatibility passes. Headset validation, native hook startup-mask confirmation and a comparable gameplay capture remain pending. No launcher, user INI, visual-quality, controller or progression changes are included.
