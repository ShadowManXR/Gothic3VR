# 0.22.24 — PUP optional prefetch maintenance for stereo

The0.22.23 capture localized roughly92–98% of the large100–430ms native-eye pauses to PVS Process. Parallel Universe Patch1.1.1 already replaces its inner Execute path. Its additional optional queue-maintenance routine uses a native5ms time-slice after complete items and runs after multiple render calls. VR adds a second eye and nested render passes. This change coordinates that optional maintenance across the stereo frame instead of disabling PUP or replacing its native scene lists.

Only the exact installed paru_s2.dll1.1.1.0 SHA25697760FFCD3EEF09B7DBCD8EF925B9995A198CB8BBA96951298969C48A84CD8F0 is supported. The optional-work entry RVA111c0 and full six-byte position-independent prologue are verified before hooking. The original ECX timestamp/DL force boolean ABI is retained. The PUP module is pinned for hook lifetime. Unknown profiles or a modified entry skip compatibility and leave the existing patch untouched. G3VR_PUP_COMPAT=0 disables this compatibility hook when starting a new process.

During ordinary application-thread VR world rendering, optional PUP maintenance gets a shared2ms allowance across both eyes and nested render passes. Already-spent native time remains included by backdating the supplied32-bit start stamp; PUP's existing post-item budget check and native queue compaction are retained. One item is never interrupted. A complete item can exceed2ms; this is a soft scheduling allowance, not a hard real-time bound or a guarantee that the100–430ms root operation is gone. Work counters and a new pup_optional_queue_work_inclusive phase distinguish this routine's cost from the encompassing PVS Process.

The optional queue is acquired through the SDK's nonblocking TryAcquire before entering the original routine. If busy, work remains owned by PUP and is retried on a later frame. If acquired, the original recursive Windows critical-section acquire/release runs unchanged inside an extra balanced acquisition, released in __finally. No native queue, entity pointer, item list or resource reference is copied or retained by the VR policy. Budget exhaustion also leaves the complete pending queue with PUP. This does not skip PVS Process, native/PUP Execute, per-eye culling, rendering or mandatory resource work.

Forced calls, disabled-threading force mode, menus/loading/outside-world contexts, world shutdown and calls outside the application-thread original-eye scope retain the original timestamp/force argument and execution. The feature is specific to optional normal VR world maintenance. Native teardown retains its own authority. Tracking, both-eye frusta, graphics fences, audio, gameplay, bow/weapon progression and user INI values are unchanged. No PUP DLL on disk or PUP configuration option is modified. The observed total PVS stalls may include other operations before this routine; those are not claimed fixed by these changes.

Startup marker: pup_vr_prefetch_compat_ready. vr_pup_prefetch reports cumulative calls/run/defer_busy/defer_budget/bypass and maximum admitted-work time. Existing scene profiler mask383 is expected with PUP: the original Execute entry stays patched by PUP; its missing profiler bit is not a compatibility failure. The new work scope is separate and nested in PVS Process. The PUP5ms comparison, complete-item boundary, queue lock identity/SDK methods, and ECX/DL entry are checked against the real file and a local x86 trampoline test.
